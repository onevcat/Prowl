# 086.002 — S1: Layout, groups, collapse, menus, and color

## Context

First implementation slice of the plan. onevcat moved the group color background from S3 into S1
(2026-10-29), because the group container exists in S1 and the color needs the same visual check.
S3 is therefore empty; S2 (drag and drop) is the only remaining slice.

## Change

- `App/Sources/Domain/SidebarLayout.swift`: `RepositoryGroup`, `SidebarLayoutItem`, and `SidebarLayout` with
  pure edits (`createGroup`, `moveRepository(_:toGroup:)`, `removeFromGroup`, `renameGroup`,
  `setGroupColor`, `ungroup`, `moveTopLevelItems`, `removeRepositories`, `normalized`). Items encode as
  `{"type": "repository", "id": …}` and `{"type": "group", "id": …, "title": …, "color": …, "repositoryIDs": […]}`.
- `App/Sources/Clients/Repositories/SidebarLayoutKey.swift`: the `SharedKey` for
  `~/.prowl/sidebar-layout.json`. Without the file, it loads the legacy `repositoryOrderIDs` app storage
  value. A file that does not decode is copied to `sidebar-layout.json.unreadable` before the fallback, because
  the next save replaces it; an item that does not decode, or an unknown group color, is skipped without dropping
  the rest. `RepositoryPersistenceClient` has `loadSidebarLayout` / `saveSidebarLayout` in place of the order
  ID functions.
- `RepositoriesFeature.State.sidebarLayout` replaces `repositoryOrderIDs`. `orderedRepositoryRoots()`
  flattens it. `pruneSidebarLayout` replaces `pruneRepositoryOrderIDs` and prunes group members too.
- `RepositoriesFeature+SidebarGroups.swift`: `SidebarGroupAction` and the title prompt
  (`GroupTitlePrompt`, `GroupTitlePromptView`). Every edit starts from `materializedSidebarLayout()`, the
  stored layout with the shown roots that it lacks at the end of the top level.
- Collapse: `sidebarCollapsedGroupIDs` (app storage, UUID strings) holds own group collapse.
  `visibleExpandedRepositoryIDs` / `visibleRepositoryIDs(ownExpanded:)` feed hotkey rows and
  `worktreeID(byOffset:)`. `SidebarListView.SidebarExpansionState` derives the header action from effective
  expansion and writes own expansion of groups and repositories. `repositoryIDsWithOpenTabs` counts all
  repository kinds.
- Reveal: `PendingSidebarReveal` carries a `SidebarScrollID` target. `revealSelectedWorktreeInSidebar` opens
  the group, and also handles a selected plain folder or workspace; its menu and palette gates accept that
  selection.
- Rendering: `SidebarItem.group(SidebarGroupModel)`, rendered by `SidebarGroupSectionView` (header, member
  rows, `RoundedRectangle` fill of the group color at 0.08 opacity). Repository and group context menus carry
  the group actions.
- S1 drag: only ungrouped top-level rows are drag sources. `repositoriesMoved` carries the
  `SidebarPresentation.topLevelKeys` that the drag used (a group is one key), so the offsets cannot index a
  different list in the reducer. Entries that the sidebar did not show keep their places.

## Deviations

- A failed repository row in a group has no group menu; Ungroup or a fixed load gives access again.
- The legacy `repositoryOrderIDs` app storage value is only read for migration and is not removed.
- A repository that leaves its group through New Group or Move to Group leaves an empty group behind, as the plan
  specifies (empty groups stay). Ungroup removes it.
