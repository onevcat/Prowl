# 086.003 — S2: Drag and drop

## Context

Second and last implementation slice of the plan. S1 shipped groups with context menus only: an
ungrouped top-level repository was the only drag source, a group was one drop position, and members
kept the order in which they joined their group.

## Change

- `App/Sources/Domain/SidebarLayout.swift`: `SidebarDragItem` (a repository or a group) and
  `SidebarDropDestination` (`.topLevel(before:)` or `.group(_:before:)`, where a nil anchor is the end).
  `SidebarLayout.move(_:to:)` is the one pure function for every drop. It rejects a group into a group,
  a missing item, and a missing anchor, and returns false for a drop that changes nothing.
  `moveTopLevelItems(visibleKeys:fromOffsets:toOffset:)` is removed.
- `RepositoriesFeature.WorktreeOrderingAction.sidebarItemMoved(_:_:)` replaces `repositoriesMoved` and
  goes through `editSidebarLayout`, so a no-op drop saves nothing.
- `App/Sources/Features/Repositories/Views/SidebarDragSupport.swift`: `SidebarDropRow` maps the drop
  location in a row to a destination:

  | Row | Repository dragged | Group dragged |
  | --- | --- | --- |
  | Top-level repository | header (top 24 pt): before it; below: after it | same |
  | Group header | top 8 pt: before the group; below: end of the group | top 12 pt: before; below: after |
  | Group member | header: before the member; below: after it | after the group |
  | Empty-group placeholder | end of the group | after the group |
  | List end (shown during a drag) | end of the top level | end of the top level |

  `SidebarLayoutDropDelegate`, `SidebarLayoutDragContext`, `sidebarLayoutDropIndicators`, and
  `sidebarLayoutDropTarget` replace the repository-only delegate and modifier. The drag payload has a
  `prowl-sidebar-group:` form.
- `SidebarListView` / `SidebarGroupSectionView`: every repository row (top level and group members) and
  every group header is a drag source. The group container draws the top-level accent lines; its header,
  member rows, and placeholder are the drop targets, so drop targets do not nest. A drop into a group
  highlights the group header.

## Deviations

- Destinations are anchors, not offsets, so the action no longer carries `visibleKeys`. Hidden entries,
  such as remote folders while the flag is off, keep their order relative to the other entries that did
  not move. Before, they kept their absolute index, so a reorder could move a shown entry across a hidden
  one (`AddRemoteFolderFeatureTests` follows the new rule).
- A repository dropped into a collapsed group stays hidden. The group does not open, the same rule as
  for selection: only an explicit reveal opens a collapsed group.
- To drop after an open group that is the last entry, use the list-end zone below it. The bottom of the
  last member puts the repository at the end of the group.
